# Pixel Art Game Studio

[← メイン README に戻る](../../README.md) · 日本語 · この翻訳は機械翻訳の支援を受けて作成されており、ネイティブスピーカーによるレビューを待っています。

<!-- section: overview -->
## 概要

Pixel Art Game Studio は、オリジナルの 2D ピクセルアートゲームを作るための Claude Code のスキル（skill）と、8 人の専門サブエージェントからなるチームです。あなたは思い描いているゲーム、今の結果で気に入らない点、次に変えたいことを伝えるだけです。Claude が作業を計画し、コードを書き、グラフィックを生成し、テストを実行し、再現できる不具合を修正し、実際に確認したことだけを報告します。

心温まる物語アドベンチャー、生活・農場シミュレーション、会話の多い RPG、見下ろし型の探索ゲーム、パズルゲームを主な対象としていますが、ほかのオリジナル 2D アイデアにも使えます。4 つの要素は分けて管理されます。**スキル**（手順と指示）、**エージェント**（専門家）、**スクリプト**（決定的に動くツール）、そして**あなたのゲーム**（独立したプロジェクトディレクトリ）です。

<!-- section: features -->
## 機能

- 大まかなアイデアを短い設計書と最小限の遊べるループに落とし込む Game Director のワークフロー。
- 責任範囲が明確で、使えるツールが制限され、決まった形式で報告する 8 人の専門家。
- プロシージャルなピクセルアート：JSON の定義から本物の PNG スプライトシート、メタデータ、プレビューを生成します。同じ定義からは常に同じバイト列ができます。
- マップ、装飾、会話、クエスト、アイテム、翻訳のためのデータ規約と、到達できない出口、ありえない会話の分岐、足りないテキストキーを見つけるバリデーター。
- 重大度レベル、再現可能な不具合報告、回帰テストで確認された修正を備えた品質保証。
- ドライラン、競合の検出、バックアップ、慎重なアンインストールに対応した安全なインストーラー。

<!-- section: agents -->
## エージェントチーム

役割は 9 つです。**Game Director** はスキルそのもので、あなたの Claude Code のメインセッションで動きます。設計を管理し、タスクの指示書を書き、すべての結果を確認し、いつ完成とするかを判断します。8 つのサブエージェントは次のとおりです。

| エージェント | 担当 |
| --- | --- |
| `pixel-artist` | アートディレクション、アセット定義、生成したスプライトとタイル |
| `npc-story-engineer` | キャラクター、分岐する会話、フラグ、クエスト |
| `world-builder-level-design` | マップの構造、当たり判定、出現地点、出口 |
| `world-builder-environmental-content` | 装飾、見どころ、地域ごとの雰囲気 |
| `ui-engineer` | メニュー、HUD、会話ウィンドウ、インベントリとセーブ画面 |
| `gameplay-engineer` | 移動、ゲーム状態、インベントリ、クエスト、セーブ |
| `qa-tester` | テスト作成、テスト実行、不具合報告 |
| `bug-fixer` | 根本原因の修正と回帰テスト |

詳しくは [AGENTS.md](../AGENTS.md) をご覧ください。

<!-- section: architecture -->
## アーキテクチャ

Director はサブエージェントではなくスキルです。あなたの依頼を直接見て、唯一の正しい情報源（`design/GAME_DESIGN.md`、`ART_DIRECTION.md` と、ほかに 5 つの短い文書）を管理する必要があるからです。専門家は指示書を受け取り、自分の担当ファイルだけを編集して報告を返します。ほかのエージェントを起動することはできません。ゲームの内容はエンジンに依存しない `data/` フォルダーに置かれるため、物語、レベル、環境の作業を並行して進められ、エンジンを起動せずに確認できます。サブエージェントが使えない場合は、Director が同じ手順を自分で順番に実行します。[ARCHITECTURE.md](../ARCHITECTURE.md) を参照してください。

<!-- section: prerequisites -->
## 前提条件

- Claude Code（バージョン 2.1.312 で確認済み）。
- Python 3.9 以降。追加のパッケージは不要です。
- 実際のゲームには、選んだエンジン（たとえば Godot 4 や MonoGame 用の .NET SDK）が必要です。スキルはインストール済みのものを確認し、何かをインストールする前に必ず確認を求めます。

<!-- section: installation -->
## インストール

リポジトリをクローンしてから、インストール方法を選びます。変更内容はまず `--dry-run` で確認してください。

```bash
python scripts/install.py --scope project --project-dir ../my-game --dry-run
python scripts/install.py --scope project --project-dir ../my-game
python scripts/install.py --scope user
```

プロジェクトスコープは `<project>/.claude/` に、ユーザースコープは `~/.claude/` に書き込みます。インストーラーが作成していない既存のファイルが置き換えられることはありません。インストールを更新するには `--update` を使います（古いファイルはバックアップされます）。`--uninstall` は、インストーラーが入れて変更されていないファイルだけを削除します。このリポジトリの中で直接 Claude Code を起動したり、フォルダーを手動でコピーしたりすることもできます。すべての方法は [INSTALLATION.md](../INSTALLATION.md) にあります。

<!-- section: quick-start -->
## クイックスタート

プロジェクトのフォルダーで Claude Code を開き、次のように入力します。

```text
/pixel-art-game-studio 小さな町、森、3 人の NPC、分岐する会話、昼と夜のサイクル、セーブ機能を備えた、オリジナルで心温まる見下ろし型のピクセルアートゲームを作って。
```

Director は妥当な初期設定を選び、短い設計書を書き、まず小さな遊べるバージョンを作ります。特定の専門家を直接呼ぶには、たとえば `@agent-qa-tester` のように名前を書きます。

<!-- section: examples -->
## 依頼の例

```text
/pixel-art-game-studio 霧のかかった湿地を追加して。NPC を 2 人と、エンディングが 2 つあるクエストを入れて。
/pixel-art-game-studio 町が寂しく見える。細かな飾りや小さな発見を足して、でも道はふさがないで。
/pixel-art-game-studio このゲームを調べて、使えるテストをすべて実行し、再現できる不具合を直して。
```

依頼はどの言語で書いてもかまいません。完全な例は [examples](../../examples/example-game-idea.md) にあります。

<!-- section: workflows -->
## ワークフロー

- **ゲームを作る**：アイデアから納品までの 14 段階。最初に最小限の遊べるループを作ります。
- **ゲームを拡張する**：既存のプロジェクトを調べ、最小で一貫した変更を行い、回帰がないか確認します。
- **テストと修正**：実際のテストを実行し、不具合を報告し、確認された不具合を限られた回数の試行で修正します。
- **アセットを生成する**：まずアートディレクションを決め、次に定義、PNG ファイル、プレビューを作ります。
- **リリースチェック**：根拠のある判定を出します。準備完了、既知の問題ありで準備完了、または未完了です。

概要は [WORKFLOWS.md](../WORKFLOWS.md) にあります。

<!-- section: testing -->
## テストと不具合修正

QA テスターは、ゲームが実際にどのツールを持っているかを調べ、受け入れ基準をテストに変換して実行し、重大度、手順、証拠を含む不具合報告を書きます。バグ修正担当は、まず各不具合を再現し、根本原因を直し、回帰テストを追加して、もう一度チェックを実行します。テストを弱めたり削除したりすることは決して許されません。このリポジトリ自体をテストするには次を実行します。

```bash
python -m unittest discover -s tests -v
python scripts/validate_repository.py
```

詳細は [TESTING.md](../TESTING.md) をご覧ください。

<!-- section: limitations -->
## 制限事項

- 単独で完成した商用ゲームを作るものではありません。あなたのフィードバックとともに育つ、動く土台ができると考えてください。
- エンジンがインストールされていない場合、確認できるのはデータ、アセット、エンジンに依存しないロジックだけです。
- 構造的なチェックでは、絵が美しいか、ゲームが楽しいかは判断できません。それには人の目が必要です。
- 翻訳は機械翻訳の支援によるもので、ネイティブスピーカーのレビューを待っています。

<!-- section: troubleshooting -->
## トラブルシューティング

スキルが表示されない場合は、`SKILL.md` が `.claude/skills/pixel-art-game-studio/` にあるか確認してください。エージェントが見つからない場合は、`.claude/agents/` を作成したあとで Claude Code を再起動してください。インストーラーがコード 2 で終了した場合は、自分で作成していないファイルを見つけたということです。表示された計画を読んでください。ほかの回答は [TROUBLESHOOTING.md](../TROUBLESHOOTING.md) にあります。
