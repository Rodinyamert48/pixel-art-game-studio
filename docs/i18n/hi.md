# Pixel Art Game Studio

[← मुख्य README पर लौटें](../../README.md) · हिन्दी · यह अनुवाद मशीन की सहायता से तैयार किया गया है और मातृभाषी समीक्षा की प्रतीक्षा में है।

<!-- section: overview -->
## परिचय

Pixel Art Game Studio, Claude Code के लिए एक स्किल (skill) है, जिसके साथ आठ विशेषज्ञ सबएजेंट की एक
टीम आती है। इसका उद्देश्य मौलिक 2D पिक्सेल-आर्ट गेम बनाना है। आप बस उस गेम का वर्णन करते हैं जिसकी
आप कल्पना करते हैं, मौजूदा नतीजे में आपको क्या पसंद नहीं है, और आगे क्या बदलना है। Claude काम की
योजना बनाता है, कोड लिखता है, ग्राफ़िक्स बनाता है, टेस्ट चलाता है, दोहराई जा सकने वाली गड़बड़ियों को
ठीक करता है और केवल वही बताता है जिसकी उसने सचमुच जाँच की है।

यह आरामदायक कहानी-आधारित रोमांच, जीवन और खेती के सिमुलेशन, संवाद-प्रधान RPG, ऊपर से दिखने वाले
खोज-आधारित गेम और पहेली गेम के लिए बनाया गया है, लेकिन दूसरे मौलिक 2D विचारों के लिए भी काम करता
है। चार हिस्से अलग रखे जाते हैं: **स्किल** (निर्देश), **एजेंट** (विशेषज्ञ), **स्क्रिप्ट**
(हमेशा एक जैसा परिणाम देने वाले टूल) और **आपका गेम** (उसकी अपनी प्रोजेक्ट डायरेक्टरी)।

<!-- section: features -->
## विशेषताएँ

- Game Director की कार्यप्रणाली, जो एक ढीले विचार को छोटे डिज़ाइन और सबसे छोटे खेलने योग्य लूप
  में बदलती है।
- आठ विशेषज्ञ, जिनकी ज़िम्मेदारियाँ साफ़ हैं, टूल सीमित हैं और रिपोर्ट एक तय ढाँचे में होती है।
- प्रोसीजरल पिक्सेल आर्ट: JSON विवरण से असली PNG स्प्राइट शीट, मेटाडेटा और प्रीव्यू बनते हैं। एक
  ही विवरण से हमेशा वही बाइट्स बनते हैं।
- नक्शों, सजावट, संवाद, क्वेस्ट, वस्तुओं और अनुवाद के लिए एक डेटा अनुबंध, और एक वैलिडेटर जो
  पहुँच से बाहर के निकास, असंभव संवाद शाखाएँ और छूटी हुई टेक्स्ट कुंजियाँ ढूँढता है।
- गुणवत्ता जाँच, जिसमें गंभीरता के स्तर, दोहराई जा सकने वाली बग रिपोर्ट और रिग्रेशन टेस्ट से पुष्टि
  किए गए सुधार शामिल हैं।
- एक सुरक्षित इंस्टॉलर, जिसमें ड्राई रन, टकराव की पहचान, बैकअप और सावधानी से हटाने की सुविधा है।

<!-- section: agents -->
## एजेंट टीम

कुल नौ भूमिकाएँ हैं। **Game Director** स्वयं स्किल है और आपके मुख्य Claude Code सत्र में चलता है:
यह डिज़ाइन सँभालता है, काम के विवरण लिखता है, हर नतीजे की जाँच करता है और तय करता है कि काम कब पूरा
हुआ। आठ सबएजेंट ये हैं:

| एजेंट | ज़िम्मेदारी |
| --- | --- |
| `pixel-artist` | कला निर्देशन, एसेट विवरण, बनाए गए स्प्राइट और टाइल |
| `npc-story-engineer` | पात्र, शाखाओं वाले संवाद, फ़्लैग, क्वेस्ट |
| `world-builder-level-design` | नक्शे की बनावट, टकराव, शुरुआती बिंदु, निकास |
| `world-builder-environmental-content` | सजावट, दिलचस्प जगहें, हर क्षेत्र का माहौल |
| `ui-engineer` | मेन्यू, HUD, संवाद बॉक्स, इन्वेंटरी और सेव स्क्रीन |
| `gameplay-engineer` | चलना-फिरना, गेम की स्थिति, इन्वेंटरी, क्वेस्ट, सेव करना |
| `qa-tester` | टेस्ट, टेस्ट चलाना, बग रिपोर्ट |
| `bug-fixer` | मूल कारण का सुधार और रिग्रेशन टेस्ट |

अधिक जानकारी: [AGENTS.md](../AGENTS.md)।

<!-- section: architecture -->
## संरचना

Director एक स्किल है, सबएजेंट नहीं, क्योंकि उसे आपके अनुरोध देखने होते हैं और सच्चाई का एक ही स्रोत
सँभालना होता है (`design/GAME_DESIGN.md`, `ART_DIRECTION.md` और पाँच और छोटे दस्तावेज़)। विशेषज्ञों
को काम का विवरण मिलता है, वे केवल अपनी फ़ाइलों पर काम करते हैं और रिपोर्ट लौटाते हैं; वे दूसरे
एजेंट शुरू नहीं कर सकते। गेम की सामग्री इंजन से स्वतंत्र `data/` फ़ोल्डर में रहती है, इसलिए कहानी,
लेवल और परिवेश का काम साथ-साथ हो सकता है और इंजन चलाए बिना जाँचा जा सकता है। अगर सबएजेंट उपलब्ध
नहीं हैं, तो Director वही कदम एक-एक करके ख़ुद पूरे करता है। देखें [ARCHITECTURE.md](../ARCHITECTURE.md)।

## आवश्यकताएँ

- Claude Code (संस्करण 2.1.312 के साथ जाँचा गया)।
- Python 3.9 या उससे नया; कोई अतिरिक्त पैकेज नहीं चाहिए।
- असली गेम के लिए आपका चुना हुआ इंजन, जैसे Godot 4 या MonoGame के लिए .NET SDK। स्किल जाँचता है
  कि क्या इंस्टॉल है और कुछ भी इंस्टॉल करने से पहले आपसे पूछता है।

<!-- section: installation -->
## इंस्टॉलेशन

सबसे आसान तरीका है इसे Claude Code के भीतर से प्लगइन के रूप में इंस्टॉल करना। तब स्किल का नाम `/pixel-art-game-studio:pixel-art-game-studio` हो जाता है और एजेंटों के नाम के आगे `pixel-art-game-studio:` जुड़ जाता है:

```text
/plugin marketplace add Rodinyamert48/pixel-art-game-studio
/plugin install pixel-art-game-studio@pixel-art-game-studio
```

या प्लगइन व्यवस्था के बिना: रिपॉज़िटरी क्लोन करें, फिर इंस्टॉल करने का तरीका चुनें। हर बदलाव को पहले `--dry-run` से देख लें:

```bash
python scripts/install.py --scope project --project-dir ../my-game --dry-run
python scripts/install.py --scope project --project-dir ../my-game
python scripts/install.py --scope user
```

प्रोजेक्ट स्कोप `<project>/.claude/` में लिखता है और यूज़र स्कोप `~/.claude/` में। जो फ़ाइलें पहले
से मौजूद हैं और इंस्टॉलर ने नहीं बनाईं, उन्हें कभी बदला नहीं जाता। इंस्टॉलेशन को नया करने के लिए
`--update` का उपयोग करें (पुरानी फ़ाइलों का बैकअप लिया जाता है), और केवल उन बिना बदली फ़ाइलों को
हटाने के लिए जो उसने इंस्टॉल की थीं, `--uninstall` का उपयोग करें। आप इसी रिपॉज़िटरी में सीधे Claude
Code भी चला सकते हैं या फ़ोल्डर हाथ से कॉपी कर सकते हैं। सभी विकल्प [INSTALLATION.md](../INSTALLATION.md)
में हैं।

## जल्दी शुरुआत

अपने प्रोजेक्ट फ़ोल्डर में Claude Code खोलें और लिखें:

```text
/pixel-art-game-studio एक मौलिक, आरामदायक, ऊपर से दिखने वाला पिक्सेल-आर्ट गेम बनाओ जिसमें एक छोटा शहर, एक जंगल, तीन NPC, शाखाओं वाले संवाद, दिन-रात का चक्र और सेव करने की सुविधा हो।
```

Director समझदारी भरे डिफ़ॉल्ट चुनता है, एक छोटा डिज़ाइन लिखता है और पहले एक छोटा खेलने योग्य
संस्करण बनाता है। किसी एक विशेषज्ञ को सीधे बुलाने के लिए उसका नाम लिखें, जैसे `@agent-qa-tester`।

## अनुरोधों के उदाहरण

```text
/pixel-art-game-studio कोहरे वाला एक दलदली इलाका जोड़ो, जिसमें दो NPC और दो अंत वाला एक क्वेस्ट हो।
/pixel-art-game-studio शहर ख़ाली लगता है। बारीक सजावट और छोटी खोजें जोड़ो, पर रास्ते खुले रखो।
/pixel-art-game-studio इस गेम की जाँच करो, सभी उपलब्ध टेस्ट चलाओ और दोहराई जा सकने वाली गड़बड़ियाँ ठीक करो।
```

आप अपने अनुरोध किसी भी भाषा में लिख सकते हैं। पूरा उदाहरण [examples](../../examples/example-game-idea.md)
में है।

## कार्यप्रवाह

- **गेम बनाना**: विचार से डिलीवरी तक 14 चरण, शुरुआत सबसे छोटे खेलने योग्य लूप से।
- **गेम बढ़ाना**: मौजूदा प्रोजेक्ट की जाँच, सबसे छोटा सुसंगत बदलाव, और रिग्रेशन की जाँच।
- **टेस्ट और सुधार**: असली टेस्ट चलाना, बग की रिपोर्ट करना, और पुष्टि हुए बग को सीमित प्रयासों में
  ठीक करना।
- **एसेट बनाना**: पहले कला निर्देशन, फिर विवरण, PNG फ़ाइलें और प्रीव्यू।
- **रिलीज़ जाँच**: सबूत पर आधारित फ़ैसला: तैयार, ज्ञात समस्याओं के साथ तैयार, या अभी तैयार नहीं।

सारांश: [WORKFLOWS.md](../WORKFLOWS.md)।

<!-- section: testing -->
## टेस्टिंग और बग सुधार

QA टेस्टर पता लगाता है कि गेम के पास असल में कौन-से टूल हैं, स्वीकृति मानदंडों को टेस्ट में बदलता
है, उन्हें चलाता है और गंभीरता, कदम और सबूत के साथ बग रिपोर्ट लिखता है। बग फ़िक्सर हर बग को पहले
दोहराता है, मूल कारण ठीक करता है, रिग्रेशन टेस्ट जोड़ता है और जाँच फिर से चलाता है। टेस्ट को कमज़ोर
करना या हटाना कभी स्वीकार नहीं है। इस रिपॉज़िटरी की जाँच के लिए:

```bash
python -m unittest discover -s tests -v
python scripts/validate_repository.py
```

विवरण: [TESTING.md](../TESTING.md)।

<!-- section: limitations -->
## सीमाएँ

- यह अपने आप तैयार व्यावसायिक गेम नहीं बनाता; एक चलने वाली नींव की उम्मीद करें जो आपकी
  प्रतिक्रिया के साथ बढ़ती है।
- इंजन इंस्टॉल न होने पर केवल डेटा, एसेट और इंजन से स्वतंत्र तर्क की जाँच हो सकती है।
- संरचनात्मक जाँच यह नहीं बता सकती कि चित्र सुंदर हैं या गेम मज़ेदार है; इसके लिए इंसान की ज़रूरत
  है।
- अनुवाद मशीन की सहायता से बने हैं और मातृभाषी समीक्षा की प्रतीक्षा में हैं।
